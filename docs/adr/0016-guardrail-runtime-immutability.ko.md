# ADR 0016 — 가드레일 규칙은 런타임에 변경할 수 없다

- **상태**: 채택 (Accepted)
- **일자**: 2026-08-12
- **맥락**: bkit v2.1.36, GitHub 이슈 [#148](https://github.com/popup-studio-ai/bkit-claude-code/issues/148)
- **대체 대상**: 없음
- **관련**: ADR 0006 (CC 업그레이드 정책), `lib/control/destructive-detector.js`, `test/security/integrity-verification.test.js` (IV-09)

## 배경

Destructive Detector는 21개의 알려진 패턴 규칙 중 하나에 걸리는 명령을 거부합니다.
거부할 때는 사용자에게 다음에 무엇을 해야 하는지 알려주어야 합니다.

v2.1.36 이전까지 거부 메시지는 이렇게 말했습니다.

> To proceed, adjust guardrail settings in bkit.config.json or use manual override.
> (진행하려면 bkit.config.json에서 guardrail 설정을 조정하거나 수동 오버라이드를 사용하세요.)

**두 경로 모두 존재하지 않았습니다.**

1. `lib/control/destructive-detector.js`는 `bkit.config.json`을 읽지 않습니다.
   해당 문자열은 파일 전체에서 **정확히 한 번** — 그 메시지 안에서만 — 등장했습니다.
2. `disableRule()`은 `rule._disabled = true`를 설정하지만 `detect()`는 그 플래그를
   전혀 확인하지 않습니다. 실측 결과, `disableRule('G-001')` 호출 전후로 매칭된
   규칙 목록이 동일했습니다.

이슈 #148은 오탐 문제와 함께 이 점을 지적하며 합리적인 질문을 던졌습니다.
설정을 배선할 것인가, 아니면 그것을 가리키기를 그만둘 것인가?

조사 결과 답이 달라졌습니다. `test/security/integrity-verification.test.js`의
IV-09가 이 무효성을 **의도적으로** 단언하고 있었습니다. 테스트 이름은
*"disableRule does not remove rule from detection"*이고, 단언 메시지는
*"Disabled rule should still detect (detect does not check _disabled flag)"*입니다.
이 동작은 **잠긴 보안 속성**이지 미완성 기능이 아니었습니다.

## 결정

**가드레일 규칙은 런타임에 비활성화할 수 없으며, 거부 메시지가 이제 그 사실을 말한다.**

구체적으로:

- `detect()`는 계속 `_disabled`를 무시합니다. IV-09는 수정 없이 유지됩니다.
- `disableRule()` / `addCustomRule()`은 API 호환성을 위해 유지하되,
  **스위치가 아니라 주석(annotation)**임을 문서화합니다. 프로덕션 호출자는 0개입니다.
- `bkit.config.json`의 `guardrails.destructiveDetection`은 **선언용**으로 문서화합니다.
  off-switch로 배선하지 **않습니다**.
- 거부 메시지는 **규칙별로** 실제 동작하는 방법만 제시합니다 — 대상을 좁히거나,
  체인 명령을 분리하거나, 의도를 명시하고 사용자 확인을 받는 것.

## 근거

세션이 끌 수 있는 가드는 그것이 존재하는 이유인 실패 유형에 대해 아무것도 보호하지
못합니다. 이 탐지기는 자신이 검사하는 명령을 내는 **바로 그 에이전트 루프 안에서**
동작하므로, 세션 내 비활성화 경로는 에이전트 스스로 발행할 수 있는 요청이 됩니다.

off-switch에 대한 압력은 오탐에서 왔고, 그 압력은 탈출구보다 **정밀도**로 답하는 것이
낫습니다. 같은 릴리스에서 16개 규칙 감사가 오탐 12건을 측정했고, 규칙을 전체 입력이
아닌 명령 세그먼트 단위로 매칭하자 1건으로 줄었습니다 — 그 1건조차 거부가 아니라
의도된 등급 변경입니다. 같은 수정이 위음성 3건도 닫았으며, 그중 `chmod 777 / ; ls`는
이전에 **아무 규칙에도 걸리지 않던** 명령이었습니다.

off-switch를 대신 출시했다면 이 릴리스에 대한 정직한 설명은 "가드가 12번 틀렸으니
끄는 방법을 드렸습니다"가 되었을 것입니다. "가드를 옳게 만들었습니다"가 아니라.

## 결과

**긍정적**

- 거부 메시지가 실행 가능해집니다. 제시하는 모든 경로가 실재합니다.
- 보안 속성이 문서화되어, 향후 변경이 테스트를 통과시키려다 실수로 이를 뒤집는 일을
  막습니다.
- `bkit.config.json`이 갖지 않은 통제력을 암시하지 않게 됩니다.

**부정적**

- 잔여 오탐을 만난 사용자에게 설정을 통한 탈출구가 없습니다. 대응은 명령을 다시
  표현하거나 신고하는 것입니다 — @Sinclair-Seo가 그렇게 했고 그래서 이 릴리스가
  나왔습니다. 신고는 영구 회귀 테스트로 흡수됩니다(`test/e2e/external-dogfood/`).
- 무인 실행이 진짜 `ask`를 만나면 여전히 답을 기다리며 멈춥니다. 오탐을 줄이면
  빈도는 줄지만 없어지지는 않습니다. 무인 실행에 프롬프트 없는 결정적 모드를 주는
  것은 별개의 설계 문제이며 **의도적으로 범위 밖**입니다.

**재검토 조건**

- 정밀도 작업 이후에도 재현 가능한 오탐이 남고 규칙을 좁혀서 고칠 수 없는 경우.
  이는 denylist 접근이 한계에 도달했다는 증거이며, 데이터를 갖고 탈출구 문제를
  다시 여는 근거가 됩니다.
- 탐지기가 자신이 감시하는 에이전트 루프 **밖에서** 실행되게 되는 경우.
  이 결정이 근거하는 신뢰 경계가 바뀝니다.
